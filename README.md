# Северное сияние — Мурманская область

Дашборд прогноза северного сияния для семи точек Мурманской области: текущий Kp-индекс, облачность по ярусам, оценка шанса увидеть сияние и лучшее время для наблюдения ближайшей ночью.

**[Открыть живую версию →](https://auroramurmansk.ru/)**

![Дашборд прогноза северного сияния: переключатель языка, выбор точки наблюдения, вкладки «Сейчас», «Куда ехать ночью» и «Настройки», вердикт с учётом Луны, окно наблюдения, Kp-индекс, облачность по ярусам и прогноз Kp на трое суток](screenshot.png)

Интерфейс на трёх языках — русском, английском и китайском: в Мурманск за сиянием едут туристы со всего мира (см. [Языки](#языки)).

HTML, CSS и чистый JavaScript. Без фреймворков, без сборки, без зависимостей: страница — это несколько статических файлов и браузер. Необязательная серверная часть — только для уведомлений при закрытом приложении (см. [ниже](#уведомления-при-закрытом-приложении)).

## Запуск

Двойной клик по `index.html` обычно работает: оба API отдают `Access-Control-Allow-Origin: *`. Если браузер всё же заблокирует запросы со страницы, открытой по `file://`, поднимите локальный сервер:

```bash
python -m http.server 8765
```

и откройте `http://localhost:8765`.

## Что показывает

Пять вкладок: **«Сейчас»** — условия в выбранной точке, **«Куда ехать ночью»** — сравнение всех семи точек на ближайшую ночь, **«Карта»** — семь точек на схеме области, **«Гид»** — советы для туриста, **«Настройки»** — вид и единицы, а ниже уведомления: проверка и настройка. Вкладка запоминается и отражается в адресе (`#now`, `#tonight`, `#map`, `#guide`, `#settings`), так что ссылкой можно поделиться; старые ссылки `#notify` открывают «Настройки». На широком экране навигация сверху, на узком — внизу экрана и листается вбок; выбранная вкладка сама доезжает до середины панели.

Облачность для всех семи точек запрашивается **одним** запросом к Open-Meteo: API принимает список координат через запятую и возвращает массив в том же порядке. Kp и его прогноз переиспользуются с первой вкладки — это планетарные величины, одинаковые для всей области.

Данные второй вкладки грузятся при первом её открытии, а не при старте приложения, и кэшируются на тех же правилах, что остальные: три часа, пометка возраста при показе из кэша.

Если ни в одной точке условия не дотягивают до среднего, в ответе так и написано — «ехать некуда», с указанием причины. Лучшее из плохого в крупной строке не показывается, но список ниже остаётся полным: по нему видно основание для вывода.

## Точки наблюдения

Точка выбирается в шапке, выбор сохраняется в браузере. Координаты проверены по открытому геокодеру Open-Meteo (данные GeoNames), геомагнитная широта посчитана дипольным приближением IGRF для эпохи ~2025 (полюс 80.7° с. ш., 72.7° з. д.):

```
sin(φm) = sin(φ)·sin(φp) + cos(φ)·cos(φp)·cos(λ − λp)
```

|---|---|---|---|---|---|

| Териберка | 69.1609 | 35.1453 | 64,78 | минимальная | 1,1 |
| Мончегорск | 67.9397 | 32.8739 | 63,94 | заметная | 1,5 |
| Ловозеро | 68.0056 | 35.0187 | 63,72 | слабая | 1,6 |
| Кировск | 67.6148 | 33.6727 | 63,53 | заметная | 1,7 |
| Апатиты | 67.5827 | 33.4134 | 63,53 | заметная | 1,7 |
| Кандалакша | 67.1512 | 32.4128 | 63,26 | заметная | 1,8 |

Деталь, которую видно только из этой таблицы: **Териберка географически севернее Мурманска, а геомагнитно — южнее**. Геомагнитная сетка наклонена, и Териберка лежит восточнее. Её преимущество перед городом не в широте, а в отсутствии засветки.

Оговорка: дипольное приближение — не строгая скорректированная геомагнитная широта (CGM), которой пользуются в авроральной науке. В этом регионе расхождение до полуградуса, то есть до четверти единицы Kp — меньше шага самих данных NOAA.

## Как считается оценка

**Kp.** Пороги занижены относительно привычных: вся область лежит практически под авроральным овалом, и сияние здесь возможно уже при Kp 2, тогда как в средней полосе нужен Kp 5–6.

Экваториальная граница овала опускается примерно на 2° геомагнитной широты на каждую единицу Kp, то есть овал оказывается над головой при `Kp ≈ (67° − φm) / 2`. Для Мурманска это ≈ 1,1, и пороги 1 / 2 / 3, подобранные под него, уже это отражают. Поэтому шкала не считается заново для каждой точки, а якорится на Мурманск и сдвигается:

```
сдвиг = (φm Мурманска − φm точки) / 2
порог = порог Мурманска + сдвиг
```

| Kp относительно порогов точки | Балл |
|---|---|
| ≥ верхнего | 3 |
| ≥ среднего | 2 |
| ≥ нижнего | 1 |
| ниже | 0 |

Практический смысл: при типичном Kp 2,67 Мурманск получает балл 2, а Кандалакша — 1. Разница почти в целую единицу Kp между крайними точками соответствует 200 км по меридиану.

**Засветка** в расчёт не входит намеренно: это не прогнозируемая величина, а свойство места, и смешивать её с погодой в одной формуле значило бы выдавать за прогноз то, что прогнозом не является. Она появляется в списке факторов и в пояснении к вердикту — например, для Мурманска советом отъехать на 15–20 км от огней.

**Облачность.** Сияние светится на высоте 100–300 км, выше любых облаков, поэтому важна только прозрачность слоя:

| Ярус | Высота | Типичные облака | Вес |
|---|---|---|---|
| Нижний | 0–2 км | Stratus, stratocumulus | 1,0 |
| Средний | 2–7 км | Altostratus, altocumulus | 0,8 |
| Верхний | 7–12 км | Cirrus, cirrostratus | 0,35 |

Ярусы сводятся в одно число по модели случайного перекрытия:

```
итог = 1 − (1 − low) · (1 − 0,8·mid) · (1 − 0,35·high)
```

Простое сложение процентов дважды учитывает перекрытие слоёв. Сравнение на 9261 сочетании с шагом 5 % показало, что сумма упирается в потолок 100 % на 57 % пространства значений и в 19 % сочетаний объявляет небо закрытым там, где модель перекрытия видит просветы. На сплошных ярусах обе формулы совпадают тождественно.

Пороги балла: ≤ 25 % — ясно (3), ≤ 50 % — переменная облачность (2), ≤ 75 % — просветы редки (1), выше — небо закрыто (0).

**Луна** в расчёт уровня не входит — как и засветка. Полная Луна над горизонтом заметно глушит слабое сияние, но это влияет на то, что именно человек увидит, а не на то, есть ли сияние. Луна показывается фактором в вердикте («Луна: 92%, над горизонтом»), строкой в окне наблюдения («Луна 100%, над горизонтом 19:50–23:57», «зайдёт в 03:14») и среди факторов на вкладке «Куда ехать». Пояснение «яркая Луна, слабое сияние выцветет, смотрите на север, спиной к Луне» добавляется только когда Луна действительно мешает и смотреть на небо имеет смысл.

Помеха зависит от освещённости диска и высоты: низкая Луна светит в основном вдоль горизонта и небо над головой почти не засвечивает, поэтому вклад растёт до 25° над горизонтом. Считается локально, без запросов, как высота Солнца; общий код лежит в `core.js`, так что сервер уведомлений может использовать те же функции.

Положение Луны — усечённая теория Меёса («Астрономические алгоритмы», гл. 47). Точность проверена по независимому источнику, астрономическому API Морской обсерватории США (данные лежат в `tools/fixtures/usno-moon-2026.json`, тест — `tools/moon.test.mjs`):

| Что сверялось | Расхождение |
|---|---|
| 50 фаз Луны за 2026 год | в среднем 1,6 мин, наибольшее 3,1 мин |
| 38 восходов и заходов в Мурманске и Кандалакше | наибольшее 1,2 мин |
| Освещённость диска | до 1–2 процентных пунктов |
| Полярные случаи: Луна не заходит (21 декабря), не восходит (11 февраля), видна 17 минут (5 июня) | совпадают |

Один нюанс из живой проверки: осенью и зимой Луна на этой широте часто вообще не поднимается над горизонтом (максимальная высота = 90° − широта + склонение, а у Мурманска это около 21°), и это верно, а не ошибка: 21 сентября 2026 года по данным обсерватории Луна «всё время под горизонтом», как и в расчёте.

**Итог** — произведение баллов: ≥ 6 высокий, ≥ 2 средний, иначе низкий.

**Высота Солнца** считается локально для координат выбранной точки, без запросов к API. С мая по июль здесь полярный день, и при любом Kp и чистом небе сияние не видно, поэтому светлое небо принудительно опускает вердикт до низкого.

## Солнечный ветер: ближайший час

Kp описывает прошедшие три часа, поэтому о начинающейся суббуре он сообщает с опозданием. Спутники NOAA в точке L1 (1,5 млн км к Солнцу) видят солнечный ветер за 30–90 минут до того, как он дойдёт до Земли. Главное для сияния — Bz, север-юг магнитного поля ветра: когда он устойчиво южный (отрицательный), энергия ветра проходит в магнитосферу.

| Оценка | Условие |
|---|---|
| сильный южный | Bz в среднем ≤ −10 нТл за 15 минут |
| устойчиво южный | Bz в среднем ≤ −5 нТл за 20 минут |
| слабо южный | сейчас южный, но слабо или недолго |
| северный | Bz ≥ 0 |

Текущий Bz — среднее за 5 минут: поминутные отсчёты заметно дрожат. Время в пути до Земли считается по скорости ветра (1,5 млн км / скорость). Данные старше получаса за «сейчас» не выдаются — спутники иногда замолкают.

Уровень вердикта от солнечного ветра **не меняется**: это прогноз на час вперёд, а не текущее состояние. Но если шанс сейчас не высокий, небо открыто и темно, а Bz южный, к пояснению добавляется «солнечный ветер обещает рост активности в ближайший час». Расчёт — `solarWindSummary()` в `core.js`, общий с сервером на случай будущих ранних уведомлений.

Источники: `json/rtsw/rtsw_mag_1m.json` (сутки поминутных данных, около 90 КБ в сжатом виде; берётся основной поток `active`) и `products/summary/solar-wind-speed.json`. Прежние адреса `products/solar-wind/*.json` NOAA убрала — отвечают 404.

## Погода на месте

Приходит тем же запросом к Open-Meteo, что и облачность (модель ICON-EU), и хранится вместе с ней — отдельного запроса нет. Главное условие выбирается по приоритету: **туман** (коды ВМО 45/48 или видимость меньше 1 км) → **снег** → **осадки** (дождь, морось, гроза) → **сильный ветер** (порывы от 15 м/с) → «осадков нет».

Туман облачность не показывает: модель видит ясное небо, а над головой молоко. Поэтому при тумане в вердикт добавляются фактор «Туман» и пояснение; уровень шанса не меняется. Единицы следуют настройкам: при милях ветер — в милях в час, видимость — в милях; температура — °C или °F.

## Когда ехать: прогноз на 27 дней

Для тех, кто выбирает даты поездки. NOAA раз в неделю (по понедельникам) публикует таблицу `text/27-day-outlook.txt`: на каждые сутки UTC — наибольший ожидаемый Kp. Прогноз строится по вращению Солнца: области, давшие бурю, через 27 суток часто дают её снова. Точность невысокая, погода неизвестна — это ориентир, а не обещание, и карточка так и говорит.

Каждый день окрашивается по порогам Kp выбранной точки (как вердикт). В местную полночь (21:00 UTC) проверяется, будет ли ночь тёмной, и насколько светит Луна. **Лучшие даты** — подряд идущие дни с высоким уровнем, тёмной ночью и без яркой Луны (освещённость меньше 70%); яркая Луна не исключает день, если буря на 2 единицы Kp сильнее порога «высокого» — такая видна и так. Показываются до трёх сильнейших отрезков, по порядку дат.

Таблица загружается при открытии вкладки «Куда ехать» и не чаще раза в 6 часов; сохранённая годится 8 дней. Разбор и оценка — `parseOutlook27()`, `outlookDays()`, `outlookBestRanges()` в `core.js`.

## Модель NOAA OVATION

OVATION Prime считает по солнечному ветру вероятность увидеть сияние прямо над головой — на сетке 1°×1° по всей Земле, с упреждением 30–90 минут. Сияние светится на высоте 100–300 км и видно у северного горизонта за несколько сотен километров, поэтому кроме клетки самой точки берётся максимум **в поле зрения**: до 5° к северу и ±3° по долготе (на 65–70° с. ш. это около 550 × 250 км). Подпись: от 50% — «яркое сияние в поле зрения», от 30% — «вероятно», от 10% — «возможна слабая дуга у горизонта».

Облаков и светлого неба модель не учитывает — это делает вердикт, и в его уровень OVATION не входит. Файл весит около 140 КБ в сжатом виде, поэтому запрашивается не чаще раза в 15 минут (кнопка «Повторить» — всегда), а в кэш кладутся только числа по семи точкам, не сетка. Наблюдение старше полутора часов прогнозом не считается. Расчёт — `ovationSummary()` в `core.js`.

## Окно наблюдения

Вердикт относится к текущему моменту, а планировать поездку нужно на ночь, поэтому дашборд отдельно считает лучшее время ближайшей ночи. Новых запросов для этого не нужно — всё уже загружено:

- почасовая облачность по ярусам на 48 часов вперёд;
- прогноз Kp с шагом 3 часа;
- высота Солнца, которая считается локально для каждого часа.

Ночью считается ближайший непрерывный отрезок часов, когда Солнце ниже −6°. Каждому часу присваивается тот же уровень, что и вердикту: произведение баллов за Kp и облачность, с понижением до среднего, если темнота неполная (Солнце выше −12°). Окно — самый длинный непрерывный ряд часов с максимальным уровнем.

Под окном — график всей ночи, по столбцу на час: цветная полоса шанса, столбики облачности (нейтрального цвета — это не оценка, а сколько неба закрыто) и прогнозного Kp, отметка Луны, если она над горизонтом (ярче — полнее), и время. Светлые столбцы — сумерки, рамка — лучшее окно. Нажатие на час (или стрелки на клавиатуре) показывает под графиком его подробности; по умолчанию выбрано начало окна. Видно не только «когда лучше», но и почему именно тогда. Луна берётся в середине часа: если она заходит в 03:14, час 03:00–04:00 считается безлунным.

В полярный день тёмных часов не находится, и карточка честно сообщает, что темноты не будет.

## Почему выбрана эта модель прогноза

Дашборд запрашивает у Open-Meteo не суммарную облачность, а три яруса по отдельности — и при проверке выяснилось, что этим полям можно верить не у всякой модели.

Исходное наблюдение: при ярусах 6 / 3 / 0 (практически чистое небо) API отдавал суммарную облачность 62 %. Это противоречие, а не округление: при **любом** допущении о перекрытии слоёв суммарная облачность обязана лежать между максимумом яруса и суммой ярусов.

```
max(ярусы) ≤ всего ≤ min(100, сумма ярусов)
```

Проверка двенадцати моделей на 48 часах почасового ряда (17 сентября 2026, точка 68.97 / 33.07):

| Модель | Часов с нарушением неравенства | Расхождение > 30 п.п. | Среднее расхождение |
|---|---|---|---|
| `best_match` | 16 из 48 (33 %) | 23 % часов | 17 п.п. |
| `metno_seamless` | 16 из 48 (33 %) | 23 % часов | 17 п.п. |
| **`icon_eu`** | **0** | **0** | **2 п.п.** |
| `ecmwf_ifs025` | 12 (25 %) | 0 | 8 п.п. |
| `gfs_seamless` | 1 (2 %) | 0 | 1 п.п. |

Что из этого следует:

1. **`best_match` для Мурманска — это MET Norway.** Ответы `best_match` и `metno_seamless` совпали до единицы во всех четырёх полях и на всех 48 часах.
2. **У MET Norway ярусы и сумма несогласованы систематически.** Самый наглядный час: ярусы 8 / 4 / 0 при суммарной облачности 90 % — «почти ясно» и «почти сплошь» одновременно.
3. **Недостоверными выглядят ярусы, а не сумма.** С суммарными 72 % независимо согласились `icon_eu` и `gfs_seamless`, а ярусы 8 / 13 / 0 разделили только `knmi_seamless` и `dmi_seamless` — сборки, которые, судя по совпадению значений до единицы, берут их из общего источника.
4. **Расчёт по ярусам MET Norway занижал облачность.** Дашборд показывал «ясно, 18 %» в момент, когда три модели из четырёх видели 70 % и больше. После переключения на ICON-EU в тот же момент: ярусы 60 / 50 / 22, эффективная облачность 78 % при суммарной 81 %.

Поэтому модель указывается явно (`models=icon_eu`), а не отдаётся на автовыбор. ICON-EU грубее локальной скандинавской модели — сетка 7 км против ~1 км, — но её поля самосогласованы, а для расчёта по ярусам это важнее разрешения.

Название действующей модели выведено в карточке облачности, чтобы подмена источника не прошла незаметно. Модель меняется одним значением `CONFIG.weatherModel` в [`app.js`](app.js).

**Страховка.** Если оценка по ярусам и суммарная облачность всё же разойдутся больше чем на 30 процентных пунктов, в карточке появится предупреждение «данные об облачности противоречивы», а балл за облачность будет ограничен: высокий при недостоверных данных не ставится.

## Устойчивость к отказам

- Таймаут 12 секунд и одна автоматическая повторная попытка на каждый запрос.
- Три запроса независимы: падение NOAA не ломает блок погоды и наоборот.
- Последний удачный ответ каждого API сохраняется в `localStorage`. При отказе показываются сохранённые данные приглушённо, с пометкой «данные 12 минут назад» и кнопкой «Повторить». Старше трёх часов не показываются вовсе.
- Вся работа с хранилищем обёрнута в `try/catch`: в приватном режиме обращение к `localStorage` бросает исключение, при переполнении квоты падает запись. Кэш необязателен — без него дашборд работает как раньше.
- Вердикт считается и на неполных данных, с явной пометкой о неполноте.
- Автообновление раз в 5 минут плюс догоняющее обновление при возврате на вкладку.

**Почему расчёт вынесен в `core.js`.** Его используют и страница, и сервер уведомлений. ## Карта

Семь точек на схеме области, цвет — шанс на ближайшую ночь (те же данные, что на вкладке «Куда ехать»; открытие любой из двух вкладок загружает их для обеих). Нажатие на точку показывает под картой её строку из списка — окно, облачность, порог Kp, дорогу — и кнопку «Смотреть условия», которая делает её точкой наблюдения и открывает «Сейчас».

Схема — собственная, без библиотек и чужих тайлов: работает офлайн и весит около 12 КБ. Контуры области и озёр взяты из Natural Earth (общественное достояние) и собраны скриптом `tools/build-map.mjs` в `map.js`. Рамка — район семи точек, а не вся область: иначе на телефоне точки слиплись бы в пятую часть карты. Сама схема тянется по ширине, а точки — это кнопки поверх неё в CSS-пикселях: их размер не зависит от масштаба, они доступны с клавиатуры и подписаны для скринридера. Подписи Кировска и Апатитов (15 км друг от друга) разведены в разные стороны.

## Анимация запуска

При первом открытии за сеанс (новая вкладка или запуск установленного приложения) за шапкой поднимаются и гаснут пять «занавесов» сияния — зелёные, бирюзовые, фиолетовые, — заголовок переливается градиентом, а шапка, вкладки и карточки проявляются волной. Около 2 секунд, только CSS: класс `intro` на `<html>` ставит встроенный скрипт в `<head>` и снимает через 2,6 с.

Анимация ничего не задерживает — данные грузятся и считаются параллельно. Повторно в том же сеансе её нет, а при системной настройке «уменьшить движение» — нет вовсе (проверяется и в скрипте, и в CSS). Хранилище недоступно — страница просто открывается без анимации.

### Заставка первого визита

Самый первый раз на устройстве сайт открывается полноэкранной заставкой: звёздное небо, три переливающиеся ленты сияния (зелёная, бирюзовая, фиолетовая, цвета — из темы), название и регион. Около 2,8 с, затем за 0,6 с плавно растворяется в дашборд. Пропустить можно сразу: кнопкой «Пропустить» (она в фокусе, над полосой системных жестов с учётом `safe-area`), клавишей Esc или нажатием в любом месте; тогда переход — 0,25 с. Свернули вкладку — заставка тоже заканчивается.

- **Один раз на устройство**: флаг `aurora.splash` в `localStorage`. При повторных визитах заставки нет вовсе — только лёгкая анимация запуска раз за сеанс (выше). Укороченная версия на 1–1,5 с повторному посетителю ничего не сообщает, а открыть прогноз он хочет сразу — поэтому её нет. В первый визит лёгкая анимация не запускается, чтобы не было двух подряд.
- **«Уменьшить движение»** — заставки нет и флаг не ставится. Хранилище недоступно — тоже без заставки, иначе она шла бы при каждом визите.
- **Данные не ждут**: решение принимается встроенным скриптом в `<head>` до первой отрисовки, заставка — отдельный слой поверх страницы, а запросы к NOAA и Open-Meteo уходят сразу при загрузке, параллельно с анимацией.
- **Без сдвигов макета**: страница под заставкой скрыта (`visibility: hidden`), пока заполняется данными, и проявляется одновременно с исчезновением заставки.
- **Производительность**: холст сияния — в четверть разрешения экрана, растянутый (сияние и так размытое), ленты рисуются столбиками из готового градиента, звёзды — один раз. Библиотек, видео и сети нет; `splash.js` в оболочке service worker, так что офлайн заставка тоже работает.

Проверено в Chrome (телефон 375×812, DPR 3, и компьютер 1280×800): 60 кадров/с, медиана кадра 16,7 мс; при замедлении CPU в 4 раза медиана та же, дольше 50 мс — 7 кадров из ~165 (в основном при разборе скриптов на старте); CLS 0; первый запрос к данным — через 0,1 с после начала загрузки (0,4 с при замедлении).

## Поделиться

Кнопка «Поделиться» в шапке открывает окно со ссылкой на сайт на выбранном языке (`?lang=ru|en|zh`, по умолчанию — язык страницы) и её QR-кодом. Действия: «Отправить…» (системное меню, где оно есть — на телефонах), «Скопировать ссылку» и «Скачать QR для печати» — PNG по 12 пикселей на модуль, чтобы распечатать для гостей отеля или туристической группы.

QR строит библиотека [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) (Kazuhiko Arase, MIT), скопированная без изменений в `vendor/qrcode.js`. Она подгружается при первом открытии окна, а не со страницей, и лежит в оболочке service worker — работает офлайн. Коррекция ошибок уровня M, тихая зона в 4 модуля, белый фон — код читается и в тёмной теме. Сгенерированные коды для всех трёх языков проверены декодером OpenCV: распознаются в точности как нужные ссылки.

## Гид

Вкладка для туриста, статичный текст на трёх языках, пять разделов:

- **Чего ждать на самом деле** — глазом сияние бледнее, чем на фото; глазам нужно 15–20 минут на привыкание к темноте; сияние приходит волнами; смотреть на север.
- **Как читать прогноз** — что значат шанс, Kp, облачность, солнечный ветер и OVATION; где включить уведомления.
- **Снимаем на телефон** и **Снимаем на камеру** — ночной режим, упор, выдержка, ISO, фокус, баланс белого, аккумуляторы на морозе.
- **Дорога и безопасность** — погода и закрытие дороги в метель, где останавливаться, топливо и связь, лёд, пограничная зона для иностранцев.

Советов по одежде в гиде нет намеренно — это проверяет тест.

| Размер текста | обычный · крупный (×1,15) · очень крупный (×1,3) | страница масштабируется целиком |
| Открывать на вкладке | где закрыл (по умолчанию) · «Сейчас» · «Куда ехать» · «Карта» | стартовая вкладка; ссылка с адресом (`#tonight`) важнее настройки |
| Тихие часы | выкл. · 22–08 · 23–07 · 00–06 | уведомления о сиянии в эти часы не приходят — ни от страницы, ни с сервера; время по выбранному часовому поясу; пробные уведомления приходят всегда |

**Тихие часы и сервер.** Если включены уведомления с сервера, страница сообщает ему окно и часовой пояс (название IANA, например `Europe/Moscow`), и сервер сам не шлёт в это время. Сигнал не пропадает: пока «высокий» держится, подписчик остаётся подходящим и получит уведомление первым проходом после окончания тихих часов. Пропущенные не расходуют лимит отправок. Уведомления страницы в тихие часы просто пропускаются — переход уже состоялся.

**Светлая тема** — это переопределение переменных CSS: цвета в коде (`TONE`) — ссылки на переменные, поэтому перерисовка при смене темы не нужна. Контраст текста и тонов — не ниже 4,5:1 на фоне и на карточке в обеих темах, это проверяет тест.

Кнопка «Сбросить настройки» возвращает значения по умолчанию. Язык переключается в шапке и отдельной настройкой не дублируется. Расчёт шанса от настроек не зависит: меняются только слова, числа и время на экране. Недопустимое или испорченное значение в хранилище заменяется значением по умолчанию — страница не ломается.

## Языки

Переключатель «Русский · English · 中文» стоит в шапке. Какой язык показать, решается по порядку:

1. параметр в адресе — `?lang=en`, `?lang=zh`, `?lang=ru` (им удобно делиться: ссылка или QR-код для гостей отеля сразу откроется на нужном языке; выбор запоминается);
2. язык, выбранный ранее переключателем (хранится в браузере);
3. язык браузера — `zh-CN`, `zh-TW`, `zh-Hans` дают китайский, `ru-*` — русский;
4. иначе английский: гостю с французским или немецким браузером английский понятнее русского.

Что переводится: весь интерфейс, названия городов, подсказки и вердикт, тексты ошибок, диагностика уведомлений, уведомления страницы, а с сервером уведомлений — и push-уведомления при закрытом приложении. Расчёт от языка не зависит: уровень шанса при тех же Kp и облачности один и тот же на любом языке (проверяется тестом).

Как принято в языке: десятичная запятая только в русском (`4,3`, а не `4.3`), формы множественного числа берутся из `Intl.PluralRules` (1 минуту, 2 минуты, 5 минут; `1 minute`, `2 minutes`; `5分钟`), день недели и порядок слов — свои. Время везде московское (Мурманская область живёт по нему, UTC+3), 24-часовое, чтобы совпадало с расписаниями на месте.

**Как добавить язык.** Скопируйте `lang/en.js` в `lang/<код>.js`, переведите значения, подключите файл в `index.html`, `sw.js` (оболочка приложения) и добавьте язык в `I18N_LANGS` в `i18n.js`. Тест [`tools/i18n.test.mjs`](tools/i18n.test.mjs) проверит, что ключи и подстановки `{имя}` совпадают с русскими, что нет пропущенного или лишнего, и что все ключи, которые называет код, существуют.

**Оговорка о переводах.** Английский и китайский тексты написаны без носителей языка и не вычитаны ими. Смысл и числа проверены тестами, но интонация и устоявшиеся выражения (особенно в китайской версии) стоит показать носителю: правки — только в `lang/en.js` и `lang/zh.js`, код трогать не нужно.

## Уведомления о высоком шансе

Под вердиктом есть кнопка «Сообщить о высоком шансе». Разрешение браузер спрашивает только по её нажатию, после согласия приходит пробное уведомление — сразу видно, что система их пропускает. Повторное нажатие выключает.

Уведомление приходит, когда вердикт выбранной точки **переходит** в «Высокий», а не на каждом обновлении, пока он держится. Дополнительные правила:

- не чаще раза в 3 часа на точку: суббури идут волнами с таким интервалом, и сигнал на каждую волну был бы шумом;
- не приходит, если вкладка в фокусе — вердикт и так перед глазами;
- не приходит по сохранённым данным из кэша: устаревший «высокий» — не повод будить;
- первый свежий расчёт после открытия или смены точки служит только точкой отсчёта.

На вкладке **«Уведомления»** можно проверить, что всё работает. Пошаговая проверка показывает, где именно проблема: поддерживает ли браузер уведомления, выдано ли разрешение сайту, активен ли service worker, включены ли уведомления о высоком шансе и открыто ли приложение как установленное (на iPhone без этого не работает). Кнопка «Отправить пробное» шлёт уведомление сразу, «Через 10 секунд» — с задержкой, чтобы успеть свернуть приложение и проверить главный сценарий: придёт ли уведомление в фоне. Ниже — памятка, что делать, если не пришло, для Chrome и Edge, Windows, macOS, Android и iPhone.

Уведомления показываются через service worker — на Android обычный конструктор `new Notification()` не работает. Нажатие на уведомление открывает приложение или возвращает фокус уже открытому.

**Ограничение.** Сам сайт — статические файлы, и закрытая страница проснуться не может: эти уведомления работают, пока приложение открыто — во вкладке, в том числе фоновой, или в установленном окне. На телефоне система обычно приостанавливает свёрнутое приложение, так что там это скорее сигнал, пока экран не погас. Для уведомлений при закрытом приложении нужен сервер — см. следующий раздел. На iPhone уведомления доступны только в приложении, добавленном на экран «Домой».

### Уведомления при закрытом приложении

Если развёрнут [сервер уведомлений](worker/README.md), на вкладке «Настройки» появляется блок с кнопкой «Включить уведомления». Сервер — Cloudflare Worker на бесплатном тарифе: раз в 10 минут он смотрит Kp (NOAA) и облачность (Open-Meteo) для точек, на которые есть подписчики, считает вердикт тем же кодом, что и сайт, и при переходе в «Высокий» шлёт push через сервис вашего браузера. Уведомление приходит, даже когда приложение закрыто.

Правила те же: при переходе в «Высокий», не чаще раза в 3 часа, ничего по неполным данным, «высокий», который уже идёт, никого не будит. Подписка привязана к выбранной точке и переезжает вместе с выбором в шапке. Пока серверные уведомления включены, страница свои не показывает, чтобы не было двух одинаковых.

Кнопка «Через 20 секунд» проверяет главный сценарий целиком: нажмите её и сразу закройте приложение совсем — уведомление придёт с сервера.

**Пульс.** Сервер записывает время и итог каждой проверки по расписанию, а вкладка «Настройки» показывает «сервер проверял условия 4 минуты назад». Если проверок не было больше 30 минут, там появится предупреждение, что уведомления могут не прийти, — сломавшийся cron не останется незамеченным.

**Приватность.** Сервер хранит только адрес подписки браузера, выбранную точку, язык уведомлений и тихие часы с часовым поясом: ни имён, ни почты, ни координат человека. Выключение уведомлений удаляет запись, недействительные подписки удаляются автоматически. Пока в [`config.js`](config.js) не указан адрес сервера, блок скрыт, а сайт работает как раньше.

## Установка как приложение

Дашборд — PWA: в Chrome и Edge его можно установить с панели адреса, на Android — «Добавить на главный экран», на iOS — «Поделиться» → «На экран «Домой»». Запускается в отдельном окне без адресной строки, с тёмной темой системных панелей.

Service worker кэширует только оболочку приложения — `index.html`, `styles.css`, `app.js`, манифест и иконки — по стратегии cache-first. Запросы к NOAA и Open-Meteo не кэшируются вообще и всегда идут в сеть: их свежесть обеспечивает `localStorage` со своей отсечкой в три часа и пометкой возраста, а два кэша с разными правилами устаревания давали бы противоречивые показания.

Без сети дашборд открывается из кэша и показывает последние сохранённые данные приглушённо, с подписью вроде «Данные 8 минут назад» на каждой карточке.

Имя кэша версионировано (`aurora-v1`). При изменении файлов оболочки версия поднимается: `install` перезагружает файлы, минуя HTTP-кэш, `activate` удаляет предыдущую версию. Плата за cache-first — обновление применяется со следующего открытия приложения, а не в текущем сеансе.

## Поиск и превью ссылок

- **Заголовок и описание.** Во вкладке — выбранная точка и слово «прогноз» («Мурманск — прогноз северного сияния»), описание — на языке страницы. Так же называется страница в выдаче.
- **Языки для поисковиков.** Адрес без параметра выбирает язык сам (`hreflang="x-default"`), `?lang=ru|en|zh` — отдельные версии. Их связывают теги `hreflang` и `sitemap.xml`; `canonical` указывает на ту версию, по которой открыли страницу (его ставит `applyLanguage()`).
- **Превью в мессенджерах и соцсетях** (Open Graph, Twitter): статичные русские теги — эти сервисы скрипты не выполняют. Картинка `icons/og-image.png` 1200×630 — кадр заставки.
- **Структурированные данные** (JSON-LD, `WebApplication`): название, описание, бесплатность, языки, регион.
- `robots.txt` открывает сайт целиком, кроме служебных `tools/` и `worker/`.

Согласованность всего этого (адреса, размеры картинки, переводы) проверяет `tools/seo.test.mjs`. Чтобы сайт быстрее попал в выдачу, его стоит добавить в [Яндекс Вебмастер](https://webmaster.yandex.ru/) и [Google Search Console](https://search.google.com/search-console) и отправить там `sitemap.xml`; при изменениях страницы в `sitemap.xml` обновляется `lastmod`.

## Источники данных

- [NOAA SWPC](https://www.swpc.noaa.gov/) — Kp-индекс (поминутный ряд, трёхчасовой как резервный) и прогноз на трое суток.
- [Open-Meteo](https://open-meteo.com/) — облачность по ярусам и температура, модель ICON-EU.

Оба API публичные, без ключей и регистрации.

## Ограничения

Оценка ориентировочная.

- **Уровень шанса строится из трёх величин**: Kp, облачности и высоты Солнца. Засветка, Луна и погода у земли (туман, снег, осадки, ветер) показываются факторами и пояснениями, но уровень не меняют. Это намеренно, см. «Как считается оценка».
- **Kp запаздывает**: это усреднение за три часа. Более ранние признаки — Bz солнечного ветра и модель NOAA OVATION — показаны отдельными карточками, но в уровень шанса не входят.
- **Облачность — по сетке модели ICON-EU с шагом 7 км.** Локальных разрывов облаков меньше этого масштаба она не видит.
- **Горизонт почасового прогноза — 48 часов**, и окно наблюдения наследует его точность: прогноз облачности на вторую ночь заметно менее надёжен, чем на ближайшую.
- **Прогноз на 27 дней** — только ориентир: NOAA даёт по одному Kp на сутки, а погоду на такой срок не предсказать.
- **Уведомления при закрытом приложении** сервер проверяет раз в 10 минут, так что сообщение может прийти с такой задержкой.
